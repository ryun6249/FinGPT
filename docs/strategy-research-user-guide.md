# Strategy Research Lab User Guide

Strategy Research Lab is a FinGPT Auto Trading workflow for reproducible strategy research. It is not a live execution system and does not provide financial advice.

## Evidence Boundary

- Current evidence class: `repo_local_deterministic`.
- Live LLM is not required for tests; hypotheses are generated by deterministic rules.
- Protected LEAN, broker, or live-market evidence is not claimed.
- Suggested strategy changes remain `pending` until validation evidence supports acceptance.

## Where It Lives

UI:

- `/ui/#auto-trading`
- Tab: `Auto Trading`
- Cards: `Auto Trading Workbench`, `Auto Trading Control`, `Strategy Governance`, `Strategy Research Lab`

API:

- `/api/v1/quant/strategy-research/*`

Artifacts:

- `data/quant_lab/strategy_research/`

## Workflow

1. In `Auto Trading Workbench`, select the asset universe and chart asset.
2. Edit the governed JSON strategy script or generate a local-LLM draft.
3. Run dry-run validation before treating the script as usable evidence.
4. Run `Backtest signals` to create Quant backtest evidence and render internal-data entry/exit markers.
5. Review the asset evidence map so excluded, stale, or missing symbols are visible.
6. Run Bayesian optimization from the workbench or Strategy Research Lab.
7. Review `best_parameters_json` and `recommended_parameters_json`.
8. Run diagnostics to identify failure tags and cost/drawdown context.
9. Generate hypotheses and keep them pending until validation evidence is reviewed.
10. Run validation, then accept or reject strategy versions and hypotheses based on OOS, walk-forward, stability, Monte Carlo, and cost stress evidence.

## Presets

`risk_adjusted_momentum_v1`

- Default FinGPT local deterministic preset.
- Uses existing Quant Lab backtest runtime.
- Intended for local verification.

`btcusdt_4h_supertrend_research_preset`

- Prompt-compatible preset.
- Runs through a repo-local deterministic 4H Supertrend engine.
- Supports `close_confirmed` stop triggering: long exits occur only when the close falls below the trailing stop line.
- Falls back to clearly labeled synthetic 4H BTCUSDT bars when local data mart coverage is absent.
- Protected LEAN/live evidence is reported separately by runtime detection and remains fail-closed unless configured.

## Optimization

Supported methods:

- `grid_search`
- `random_search`
- `bayesian`

The Bayesian path uses Optuna TPE when `optuna` is installed. The backend status reports `bayesian_backend=optuna_tpe`. If Optuna is unavailable in a future environment, the API explicitly reports a deterministic surrogate fallback instead of silently claiming Optuna evidence.

The objective is a robust composite score. It uses Sharpe, Calmar, profit factor, expectancy, drawdown penalty, complexity penalty, low-trade-count penalty, and return-concentration penalty. It does not optimize only for win rate.

## Diagnostics

Diagnostics answer practical research questions:

- Are losses concentrated in choppy or high-volatility observations?
- Is cost drag material relative to expectancy?
- Is return concentrated in too few observations?
- Are there too few trades for the evidence to be decision-useful?
- Does drawdown behavior require rejecting an attractive parameter spike?

## Hypotheses

Hypotheses are structured records with:

- problem
- hypothesis
- proposed change
- expected effect
- risk
- validation requirements
- status

Core logic is protected. Hypotheses may propose optional filters, risk modules, exit modules, or sizing changes, but they do not automatically modify core strategy logic.

## Validation

Validation includes:

- in-sample and out-of-sample metrics
- walk-forward segments
- parameter stability neighborhood
- Monte Carlo trade-return resampling when enough evidence exists
- cost stress at 1x, 2x, and 3x costs

Acceptance requires evidence breadth. In-sample-only improvement, OOS degradation, low sample size, cost fragility, or single-spike parameters should keep a strategy version rejected.

## Known Limits

- Artifact-first JSON storage is the source of audit detail; no SQLite index was added yet.
- Optimization, diagnostics, and validation run synchronously in the MVP.
- Protected LEAN/live/broker evidence is not claimed unless `/api/v1/quant/strategy-research/protected-runtime/status` reports the runtime as available. In the default local environment it is an explicit fail-closed status, not a silent pass.
- Output is strategy research evidence, not a buy/sell recommendation.
